# HIMA-TI Design Constitution

## Project

HIMA-TI
Fakultas Sains dan Teknologi
UIN Ar-Raniry Banda Aceh

This is an official student organization website.

The website must feel intentionally designed by a professional
human designer/developer.

It must NOT look AI-generated, template-generated,
SaaS-generated, or visually generic.

---

## Core Design Direction

Editorial Technology
+
Institutional Identity
+
Intentional Motion

The visual identity must be derived from the official HIMA-TI logo.

---

## Color

Primary background:

#050505

Primary orange:

#F7931E

Light orange:

#FFB13B

Dark orange:

#C66A18

Primary text:

#F5F5F5

Secondary text:

#A1A1A1

Surface:

#0D0D0D

Border:

#262626

Orange is an accent.

Do NOT flood the interface with orange.

---

## Typography

Use a modern, highly readable sans-serif.

Typography must create hierarchy through:

- size
- weight
- spacing
- line height
- composition

Do not use futuristic or gimmicky fonts.

---

## Layout

Prefer:

- strong grid systems
- editorial layouts
- asymmetry where appropriate
- intentional whitespace
- large typography
- sharp geometric details
- varied composition
- visual rhythm

Do NOT use the same card layout repeatedly.

---

## Avoid

Never create:

- generic SaaS layouts
- excessive rounded cards
- excessive glassmorphism
- purple gradients
- blue/purple AI gradients
- random glowing blobs
- floating 3D objects without purpose
- excessive shadows
- excessive orange
- generic dashboard aesthetics
- repetitive 3-column cards
- excessive icons
- meaningless decorative elements
- generic AI copywriting
- repetitive fade-in animations

---

## Animation

GSAP is the primary animation system.

Use:

- GSAP
- ScrollTrigger
- SplitText
- useGSAP
- Lenis

Motion should communicate:

- hierarchy
- navigation
- storytelling
- interaction
- spatial relationships

Never animate something simply because it can be animated.

Avoid repetitive:

fade-in
fade-in
fade-in
fade-in

---

## Motion Philosophy

The website should still look excellent
when all animations are disabled.

Animation should enhance the design,
not compensate for weak design.

Use:

- reveal animations
- clip-path transitions
- timeline choreography
- subtle parallax
- horizontal scrolling when appropriate
- magnetic interaction selectively
- image movement
- page transitions
- typography motion

Use animation sparingly and intentionally.

---

## Responsive Design

Desktop and mobile are separate design considerations.

Do not simply shrink the desktop layout.

Mobile layouts must be intentionally composed.

---

## Content

Do not invent unrealistic organizational information.

Use placeholders only when actual HIMA-TI data
has not yet been provided.

Do not fabricate:

- member names
- achievements
- events
- statistics
- organizational departments
- contact information

---

## Engineering

Use:

- Next.js App Router
- TypeScript
- Tailwind CSS
- GSAP
- Lenis
- Lucide React

Prefer reusable components.

Keep animation logic separate from UI components where practical.

Use GSAP cleanup correctly in React.

Avoid unnecessary dependencies.

---

## Quality Rule

Before considering a section complete, ask:

1. Does it look like a real organization website?
2. Does it have its own visual identity?
3. Would it still look good without animation?
4. Is the layout too similar to common AI-generated websites?
5. Is orange being overused?
6. Is every decorative element necessary?
7. Does the animation have a purpose?
8. Does the section feel intentionally art-directed?
